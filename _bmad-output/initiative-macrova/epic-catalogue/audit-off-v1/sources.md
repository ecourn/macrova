# Sources et conditions OFF — audit v1

Consultation : 10 octobre 2026 (UTC). Sources primaires consultées en lecture seule ; aucune contribution, inscription, prise de contact ni publication effectuée. Le dossier conserve uniquement les réponses utiles aux recherches et leur traçabilité ; aucune photographie produit ni donnée utilisateur Macrova.

## Sources techniques

- [Documentation API OFF](https://openfoodfacts.github.io/openfoodfacts-server/api/) : indique v3.6 pour les nouvelles intégrations, v2 encore compatible mais dépréciée. La recherche structurée reste en v2 ; le texte libre passe par `cgi/search.pl` legacy, ou Search-a-licious à instruire. La documentation annonce 10 recherches/minute/IP et 15 lectures produit/minute/IP, une limite globale avec 503, un User-Agent identifié et staging pour les tests. Ces chiffres sont une photographie, pas une disponibilité garantie. L’audit ponctuel observe la base réelle sans écrire ; le futur adaptateur applicatif doit séparer staging et production. Choix de l’audit : une seule collecte, 8 secondes minimum entre recherches, aucune recherche à la frappe ni relance automatique après 429/503. Les observations exactes figurent dans les captures.
- [Données nutritionnelles OFF](https://openfoodfacts.github.io/openfoodfacts-server/dev/explain-nutrition-data/) : les suffixes `_value`, `_unit`, `_100g`, `_serving` et les champs `nutrition_data_per`/`serving_size` ne sont pas interchangeables. L’audit garde les champs originaux et n’infère ni kcal ni densité ni état alimentaire. Toute base non confirmée bloque son utilisation ; une quantité d’emballage en ml ne démontre pas seule la base nutritionnelle.
- [Tutoriel OFF API](https://openfoodfacts.github.io/openfoodfacts-server/api/tutorial-off-api/) : décrit sélection de champs et provenance produit. Les exemples de tutoriel ne sont pas utilisés comme captures du corpus réel.

- [Search-a-licious](https://openfoodfacts.github.io/search-a-licious/) et [référence OpenAPI](https://openfoodfacts.github.io/search-a-licious/users/ref-openapi/) : service OFF de recherche texte. Alternative retenue après suspensions du legacy, API 0.1.0, GET `/search` avec `q`, `langs=fr`, `page_size=3` et projection de champs tracés dans chaque capture. Ce service indexe les données OFF ; les dates d’index observées peuvent être antérieures à la consultation (notamment 2024). La date de capture ne rafraîchit pas les données de l’index. `nutrition_data_per` absent signifie base ambiguë : aucune unité nutritionnelle inventée. La collecte garde le même budget conservateur ; les lectures produit éventuelles sont distinctes et sourcées.

## Licences et attribution

- [Guide OFF sur les licences](https://openfoodfacts.github.io/openfoodfacts-server/api/tutorials/license-be-on-the-legal-side/) : distingue base ODbL, contenus DbCL et images CC BY-SA ; renvoie aux conditions d’utilisation. Cette distinction est conservée pour éviter d’appliquer une licence de code aux données OFF.
- [Conditions françaises OFF](https://fr.openfoodfacts.org/conditions-d-utilisation) (lecture HTTP 200 par curl le 10 octobre ; [version anglaise](https://world.openfoodfacts.org/terms-of-use) également HTTP 200) : exactitude et complétude non garanties ; attribution à OFF avec licence et lien produit pour une donnée produit ; réutilisation sous conditions, droits de tiers possibles. La version française prévaut. Le texte de conditions peut évoluer ; contrôler à nouveau avant ouverture. Aucun résultat alimentaire de cet audit ne vaut validation médicale.
- [ODbL 1.0, texte de licence](https://opendatacommons.org/licenses/odbl/1-0/) : autorise extraction et réutilisation sous conditions ; notices et attribution à conserver ; usage public d’une base dérivée soumis au partage sous licence compatible (sections 4.2–4.4) et accès à la base ou aux transformations selon 4.6. L’usage interne et la qualification de base dérivée sont distincts. Le dossier adopte ODbL pour sa sélection/organisation des données OFF ; une diffusion publique doit en conserver les avis et moyens d’accès, sans présumer que les données personnelles privées deviennent publiques.
- [DbCL 1.0](https://opendatacommons.org/licenses/dbcl/1-0/) : contenus individuels réutilisables, y compris commercialement, sous respect de l’ODbL ; absence de garantie. Les contenus alimentaires OFF conservés restent sous DbCL ; le code d’audit demeure régi par la licence du dépôt.

Attribution à accompagner de chaque export des données du dossier : **Données issues d’[Open Food Facts](https://world.openfoodfacts.org), base disponible sous [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/), contenus individuels sous [DbCL 1.0](https://opendatacommons.org/licenses/dbcl/1-0/).** Chaque snapshot fournit aussi son lien produit. Aucune image n’est reprise ici ; ajouter des images demanderait de traiter CC BY-SA et les droits de tiers.

## Décisions et limites

Les captures locales minimales, les références produit et les licences restent ensemble dans le dossier versionné pour permettre un replay et une réutilisation traçable. Ne pas mélanger corrections privées, profils, identifiants de comptes ou journaux à ce corpus public. Le cache public futur doit conserver attribution, date et provenance et suivre AD-8 ; aucun catalogue complémentaire n’est adopté.

Cette lecture sourcée instruit les conditions de conservation/réutilisation de l’audit. Avant ouverture publique, vérifier de nouveau les conditions, le périmètre exact de diffusion de la base dérivée et des transformations, les moyens d’accès, les notices dans l’interface et la séparation des données privées. Le formulaire d’usage et contact cités par la documentation n’ont pas été envoyés : toute communication externe exige un mandat explicite. Le dossier n’annonce aucune certification juridique ni activation publique.
